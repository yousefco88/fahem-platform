# خطة تحسين صفحة تسجيل الدخول والحساب (ParentAccount)

> **الحالة:** proposed — بانتظار «ابدا»
> **الهدف:** تحويل صفحة حساب ولي الأمر من نموذج خام بلا هوية إلى تجربة دخول/حساب احترافية بهوية فاهم، RTL، متجاوبة، وآمنة — دون تغيير أي منطق قاعدة بيانات.

---

## 1) تدقيق الوضع الحالي (Audit — حقائق من الكود)

**الملف:** `src/components/ParentAccount.jsx` (18 سطراً مضغوطاً، ~7KB)

| المشكلة | الدليل |
|---------|--------|
| تسريب تقني للزائر | العنوان يعرض «حساب ولي الأمر — **Supabase**» |
| لا هوية بصرية | أزرار متصفح خام بلا تنسيق (إنشاء حساب/تسجيل الدخول/إنشاء الحساب) |
| حقول بلا Labels | placeholder فقط — يختفي عند الكتابة (مشكلة وصولية) |
| كلمة المرور | لا زر إظهار/إخفاء، لا مؤشر قوة، التلميح «12 حرفاً» في placeholder فقط بلا فرض `minLength` |
| الرسائل | النجاح يُعرض بتنسيق الخطأ الأحمر (resetPassword يضع رسالة النجاح في `setError`!) |
| ازدواجية منطق | يدير الجلسة بنفسه (`getSession`/`onAuthStateChange`) بينما يوجد `AuthContext` مستخدم في `AuthGate` |
| حذف الطفل | `window.confirm` خام بالإنجليزية |
| لا حالة تأكيد البريد | بعد signUp لا يوضح للمستخدم أن عليه تأكيد بريده (إن كان مفعلاً) |
| أخطاء Supabase بالإنجليزية | "Invalid login credentials" تظهر كما هي |
| التصميم الداكن | ألوان ثابتة (#0f172a على أبيض) تتجاهل متغيرات `index.css` الداكنة |

**نقاط قوة تُحفظ كما هي (لا تمس):**
- منطق signUp/signIn/reset/children CRUD يعمل وسليم أمنياً (RLS على الجداول)
- خاصية `embedded` المستخدمة في `MySpace.jsx:228`
- `AuthGate.jsx` fail-closed سليم

**نقاط الاستخدام:** `MySpace.jsx:197` (صفحة كاملة عند عدم الدخول) و`:228` (embedded داخل مساحتي).

## 2) النهج المقترح

- **إعادة بناء الواجهة فقط** — نفس استدعاءات Supabase حرفياً (صفر تغيير في DB/auth logic)
- استخدام متغيرات التصميم الموجودة في `src/index.css` (`--navy`, `--muted`, `--line`, `--font-title`, `tag-badge`, `btn-secondary`) لدعم الوضع الداكن تلقائياً
- تقسيم الملف إلى مكونات واضحة داخل `src/components/account/`
- قاموس تعريب لأخطاء Supabase الشائعة
- YAGNI: لا OAuth، لا OTP، لا صفحات جديدة — تحسين الموجود فقط

## 3) المهام (بترتيب التنفيذ)

### المهمة 1 — بنية الملفات + قاموس الأخطاء
- **إنشاء:** `src/components/account/authErrors.js`
  - دالة `arabicAuthError(err)`: خريطة لـ: Invalid login credentials / User already registered / Email not confirmed / Password should be at least / rate limit / network → رسائل عربية واضحة، مع fallback للرسالة الأصلية
- **إنشاء:** `src/components/account/account.css` — أنماط البطاقة والحقول والتبويبات (تعتمد متغيرات index.css)
- ✅ قبول: الملفان موجودان، البناء ينجح

### المهمة 2 — مكوّن الحقل الموحد
- **إنشاء:** `src/components/account/Field.jsx`
  - label ظاهر دائماً + input + رسالة خطأ اختيارية + دعم `type="password"` بزر 👁 إظهار/إخفاء
  - `autoComplete` صحيح (email / new-password / current-password / name)
- ✅ قبول: يعمل في الوضعين الفاتح/الداكن

### المهمة 3 — إعادة بناء واجهة الدخول/التسجيل (AuthCard)
- **إنشاء:** `src/components/account/AuthCard.jsx`
  - هيدر بهوية فاهم: شعار 🎓 + «حساب الأسرة في فاهم» + سطر طمأنة (**حذف كلمة Supabase نهائياً**)
  - تبويبان مصممان (إنشاء حساب / تسجيل الدخول) بمؤشر نشط وانتقال سلس
  - تسجيل: اسم ولي الأمر، اسم الطفل، الصف (select مصمم)، البريد، كلمة المرور بمؤشر قوة بسيط + `minLength={12}` فرضاً فعلياً
  - دخول: بريد + كلمة مرور + رابط «نسيت كلمة المرور؟»
  - زر رئيسي بتدرج العلامة + حالة busy (spinner نصي «جارٍ...») + تعطيل أثناء الإرسال
  - **فصل رسائل النجاح عن الخطأ**: state منفصل `notice` (أخضر) و`error` (أحمر)
  - حالة ما بعد التسجيل: إشعار «تحقق من بريدك لتأكيد الحساب» عند غياب session في رد signUp
- ✅ قبول: جميع المسارات (تسجيل/دخول/نسيت) تعمل بنفس استدعاءات Supabase الحالية

### المهمة 4 — إعادة بناء واجهة الحساب المسجل (FamilyPanel)
- **إنشاء:** `src/components/account/FamilyPanel.jsx`
  - بطاقة ولي الأمر: أفاتار بالحرف الأول + الاسم + البريد + زر تسجيل خروج ثانوي
  - ملفات الأبناء كبطاقات (أيقونة 🧒 + الاسم + شارة الصف) بدل سطور خام
  - حذف الطفل: تأكيد عربي داخل البطاقة (زرا «تأكيد الحذف/إلغاء») بدل `window.confirm`
  - نموذج إضافة ابن/ابنة في بطاقة منفصلة بحقول Field الموحدة
  - حالة فارغة ودية عند صفر أبناء
- ✅ قبول: إضافة/حذف يعملان كما قبل

### المهمة 5 — تجميع ParentAccount + توحيد الجلسة
- **تعديل:** `src/components/ParentAccount.jsx` — يصبح غلافاً نحيفاً:
  - يستخدم `useAuth()` من `AuthContext` بدل إدارة جلسة مكررة (يبقي جلب profile/children محلياً)
  - `embedded` يحافظ على سلوكه الحالي (بلا إطار/هيدر) لتوافق MySpace
- **تعديل (طفيف):** `src/components/AuthGate.jsx` — مواءمة بصرية لـ `LoginForm/GateShell` مع نفس أنماط account.css (بدون تغيير منطق الحماية إطلاقاً)
- ✅ قبول: `MySpace` يعمل بالوضعين، AuthGate يحمي كما قبل

### المهمة 6 — تجاوب + وصولية
- موبايل ≤480px: بطاقة بعرض كامل، أزرار ≥44px لمساً
- `aria-live="polite"` للرسائل، focus-visible واضح، ترتيب Tab منطقي
- ✅ قبول: فحص بصري بالمعاينة على عرضي 375px و1280px

### المهمة 7 — تحقق شامل ونشر
1. `npm run build` → ينجح
2. معاينة مدمجة: تسجيل حساب تجريبي (بريد `test+ux@...`) → دخول → إضافة طفل → حذف → خروج → نسيت كلمة المرور
3. فحص عدم ظهور «Supabase» في أي نص واجهة
4. commit (foreground) + push (background, notify)
5. تحقق الإنتاج عبر hash البندل كما فعلنا سابقاً

## 5) المخاطر والأسئلة المفتوحة

| خطر | التخفيف |
|------|---------|
| كسر وضع embedded في MySpace | اختبار الوضعين صراحة في التحقق |
| فرض minLength=12 قد يمنع مستخدمين قدامى بكلمات أقصر من **الدخول** | الفرض على التسجيل فقط، الدخول بلا minLength |
| تأكيد البريد قد يكون معطلاً في إعدادات Supabase | المنطق يتعامل مع الحالتين (وجود/غياب session بعد signUp) |
| حساب تجريبي حقيقي في DB أثناء الاختبار | حذفه بعد الاختبار أو تمييزه بوضوح |

**سؤال مفتوح (غير حاجز):** هل تريد لاحقاً دمج صفحة دخول الإدارة (AuthGate) بنفس البطاقة الكاملة؟ الخطة الحالية تكتفي بمواءمتها بصرياً.
